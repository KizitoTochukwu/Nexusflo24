# Fix WhatsApp / Meta Embedded Signup OAuth

## What the two errors actually mean

1. **In-app red banner**: `Frontend sent https://nexusflo24.com/auth/callback, but NexusFlo24 expects https://nexusflo24.com/`.
   This is generated by our own `whatsapp-embedded-signup` edge function (line 113). The repo currently has `META_REDIRECT_URI = "https://nexusflo24.com/auth/callback"`, but the **deployed** function is stale and still has the old value `https://nexusflo24.com/`. Frontend was already updated, backend wasn't redeployed.

2. **Meta dialog error** (jpg): `Error validating verification code. Please make sure your redirect_uri is identical to the one you used in the OAuth dialog request`.
   This is Meta's actual response when the backend exchanges the `code` at `/oauth/access_token`. It fires when the `redirect_uri` passed to Graph doesn't match the one originally passed to `FB.login()` — character for character.

Both failures collapse to one root cause: the redirect_uri value isn't pinned consistently across frontend, backend, Meta App, and Supabase Auth allow-list.

## Canonical redirect URI (single source of truth)

Pin everywhere to:

```
https://nexusflo24.com/auth/callback
```

No trailing slash. No `www`. No preview URL. Embedded Signup is a popup flow so the URI is never actually navigated to — it just has to match across all four places below.

## Changes in the codebase

1. **Keep** `supabase/functions/_shared/meta.ts` as-is:
   ```ts
   export const META_REDIRECT_URI = "https://nexusflo24.com/auth/callback";
   ```
2. **Redeploy** the two affected edge functions so the live runtime matches the repo:
   - `whatsapp-embedded-signup`
   - `whatsapp-embedded-config`
3. No frontend code changes needed — `src/lib/meta/fbSdk.ts` already imports `META_REDIRECT_URI` from the shared file and passes it to `FB.login()` (line 197) with `response_type: "code"` and `override_default_response_type: true`.

## Configuration in Meta Developer Console

App ID that owns config_id `945252895216570` → **App Settings → Use cases → Login with Facebook → Settings** (or legacy "Facebook Login → Settings"):

- **Use Strict Mode for redirect URIs**: Yes (keep it on).
- **Valid OAuth Redirect URIs** — make sure this exact entry is present:
  - `https://nexusflo24.com/auth/callback`

  Your current list already includes it, plus extras (`/`, `/*`, www, preview, lovable.app). Those don't hurt, but the one above is the one that must be there. Click **Save changes**.

- **App Domains** (App Settings → Basic): must include `nexusflo24.com`.
- **Site URL** (Basic → + Add Platform → Website): `https://nexusflo24.com`.
- **App Mode**: Live (not Development), or the connecting Facebook user must be a listed App Tester / Developer.
- **WhatsApp product** added, and Embedded Signup configuration `945252895216570` must belong to **this same app**. If the config_id was created under a different Meta app, the code exchange will always fail because `client_id`/`client_secret` won't match the dialog. Verify by opening the config in Meta → WhatsApp → Configurations.

## Configuration in Supabase Auth (already correct, just confirm)

This OAuth is Meta → our backend, not Supabase Auth, so Supabase's Redirect URLs list is **not** what Meta validates against. But to keep our own `/auth/callback` route reachable for Google sign-in:

- **Site URL**: `https://nexusflo24.com` ✓ (already set)
- **Redirect URLs**: keep `https://nexusflo24.com/auth/callback` and the `www` + lovable.app variants ✓

No changes needed here.

## Secrets to verify (no values shown)

In the backend secrets, confirm all three belong to the **same** Meta app as config_id `945252895216570`:

- `META_APP_ID`
- `META_APP_SECRET`
- `META_EMBEDDED_SIGNUP_CONFIG_ID` = `945252895216570`

If `META_APP_ID`/`META_APP_SECRET` are from a different app than the config_id, Meta returns exactly the "redirect_uri is identical" error you're seeing — the dialog issued the code against app A, the exchange tried to redeem it as app B. This is the most common cause when the URL list already looks correct.

## Verification flow after deploy

1. Hard refresh `https://nexusflo24.com/dashboard/.../settings` (Channels tab).
2. Click **Connect WhatsApp via Meta**.
3. Complete the popup (Business → WABA → Phone Number).
4. Expected: green "Connected" badge.
5. If it still fails, open the `whatsapp-embedded-signup` function logs. The function now logs:
   - frontend redirect_uri received
   - expected redirect_uri
   - Meta exchange response (status + error code/subcode)
   That triple makes the exact remaining mismatch visible in 5 seconds.
